# Approved Shady citywide MVP brief
Build in ~/Developer/shady using React Native, TypeScript, Expo Router, maps, location, TanStack Query, Reanimated, Gesture Handler, Gorhom Bottom Sheet v5; Python 3.12 / uv / FastAPI / Pydantic / OSMnx / NetworkX / Shapely / GeoPandas / pyproj / pvlib / lxml. Install and apply vercel-react-native-skills, apple-design, and frontend-design.

Support endpoints and connected OSM public walking paths across Kraków's administrative polygon, preserving disconnected graph components. Snap to edges within 100 m and split edges; expose offsets and actionable errors. No walking-distance cap.

Use real GUGiK LoD1 2024 buildings, including neighboring data for incoming shadows. Prepare boundary, buildings, walking graph, indexes and version/source metadata locally; no acquisition during route requests. pvlib sun position; vertical footprint extrusion over flat ground; preserve concavity/courtyards. Cache 500 m tiles by dataset and ten-minute time, including a height/elevation-based halo. Send visible simplified display geometry while routing uses full geometry. Street detail only, with a zoom prompt at city scale.

Compute shortest distance D, then bound eligible edges by distances from both endpoints under 1.25D. Candidate costs = length + lambda*sunny length for lambda 0,1,2,4,8,16,32. Reject over-cap routes; select minimum sunny length then distance. Explain heuristic limits. Walking 1.3 m/s, Europe/Warsaw, shade at departure, night has no artificial 100% shade; elevation under 5 degrees has unavailable estimates. Trees, clouds, terrain and shade changes during the walk are excluded.

API: GET /health readiness; GET /v1/metadata polygon/bounds/sources/version/timezone/model/demo; GET /v1/search up to five submitted results within the polygon; POST /v1/routes alternatives/segments/metrics/snaps/status; GET /v1/shade viewport/time/version/detail. Proxy Nominatim with identifying User-Agent, attribution, caching, total one request/second and no autocomplete. Keep heavy calculation off the API event loop.

UI: playful map-first, palette #F5FAF8 / #123B35 / #168575 / #D8EFEA / #FFC857, system type, rounded floating controls and restrained sun character. Destination/Now above map, GPS/shade tools, 15/35/70% results sheet, selectable Shortest/More shade cards emphasizing extra minutes and sunny distance saved. Finger tracking, interruptible critically damped springs, momentum response, selection haptics, reduced motion, scaling/safe areas/44-point targets. Dragging time updates labels immediately, calculation commits on release. Commit route/map/metrics consistently, retain old results labeled Updating, discard stale responses, allow map interactions during calculation.

Run laptop server on LAN/hotspot via EXPO_PUBLIC_API_URL. Explicit Saved demo with bundled real summer scenarios at 10/13/16 and local SVG map after Expo loads; never silently replace arbitrary failed requests. Supply reproducible setup, attribution and recorded walkthrough. Reserve final UI polish. Native phone checks remain necessary.

Acceptance: TDD red/green per behavioral slice, pytest/HTTPX and jest-expo/RNTL, mock external/native boundaries rather than calculations. Python core >=95% lines and >=90% branches; critical mobile >=90% both. Cover geometry, timestamps, snapping, permission/search/failures/stale responses, cross-tile/city shadows, cache equivalence, components/import, multi-tile detours, snapshot consistency, longer routes. Verify Stare Miasto, Podgórze, Nowa Huta, western Kraków and a cross-district route. Measure cold/warm on laptop with targets <10s/<2s; report actual limits. Device checks: sheet gestures, rapid switching, keyboard, reduced motion/larger text, map during computation, saved offline operation.

Review focus: graph overlay isolation and direction, courtyard and tile halo math, geographic boundary enforcement, low-sun/night truthfulness, asynchronous request cancellation/snapshot matching, offline/live distinction, access restrictions, data versioning, long-request responsiveness, native limitations and reproducibility. Browser/static exports cannot prove physical native performance.
